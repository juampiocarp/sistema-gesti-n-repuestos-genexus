# Análisis y modelado

## Relevamiento

El trabajo comenzó con una entrevista al responsable del comercio para conocer:

- La organización y los roles de trabajo.
- Cómo se registraban las ventas y los cobros.
- Cómo se controlaba el inventario.
- Cómo se realizaban pedidos y compras a proveedores.
- Qué información necesitaba consultar cada tipo de usuario.
- Qué expectativas existían sobre facilidad de uso, acceso y seguridad.

Los datos identificatorios del comercio y las respuestas que puedan revelar información privada fueron omitidos de esta versión pública.

## Modelado funcional

El documento académico incluye un diagrama de contexto y diagramas de casos de uso para representar interacciones entre actores y funcionalidades del sistema.

El modelado se utilizó como soporte para delimitar el alcance, identificar operaciones y documentar el comportamiento esperado.

## Estructura de datos

El trabajo incluye especificaciones de tablas, atributos, tipos de datos, claves primarias y relaciones mediante claves foráneas. Entre las entidades documentadas se encuentran:

- Clientes.
- Usuarios.
- Proveedores.
- Productos.
- Categorías.
- Compras y detalles de compra.
- Ventas y detalles de venta.
- Imágenes de productos.
- Descuentos.

La documentación original describe atributos como identificadores, nombres, datos de contacto, stock, precios, fechas y referencias entre registros. No se publican datos reales ni registros de la base de datos.

## Consideraciones

La documentación consultada contiene especificaciones tabulares del modelo de datos. Por eso, esta página describe la estructura sin presentar un diagrama entidad-relación reconstruido como si fuera una imagen original del proyecto.
